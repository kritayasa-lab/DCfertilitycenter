# Admin CMS requirements (future phase)

Status: **planning document only**. Nothing here is implemented yet. No database, no persistence,
no admin routes and no Supabase or Google Apps Script connection exist in this release.

## 0. Current state and constraints

- **No admin UI exists** in the repository. A non-persistent admin prototype was **deliberately not
  built**: without authentication in place it could not be kept safe from public access, and fake
  "save" behaviour is not allowed. The admin UI is built in Phase 4, after Phase 3 (auth + database).
- Route convention (approved): `/<locale>/admin/*`, with a separate staff login at
  `/<locale>/admin/login`. Never linked from public navigation. Authorization is enforced on the
  server for every read and write and in the database (Row Level Security), never by URL or by
  hidden buttons.
- Public pages already read content only through `src/content/queries.ts` and
  `src/config/site.ts`. Phase 4 swaps those implementations for database reads, so page components
  don't change.
- Current data shapes to migrate: `src/content/types.ts` (Service, Doctor, Package, Article, Faq,
  PromoSlide, SuccessStory), `src/config/site.ts` (SiteConfig) and `src/config/assets.ts`
  (approved images).

## 1. Cross-cutting rules (apply to every section)

### 1.1 Localization model

Every editable record = **base row** (language-independent fields) + **one translation row per
locale** (`th`, `en`, `zh-CN`). Translation fields:

| Field | Type | Notes |
|---|---|---|
| `locale` | enum `th`/`en`/`zh-CN` | unique per base row |
| `status` | enum `draft` / `in_review` / `approved` | only `approved` translations are publishable |
| `machine_translated` | boolean | if true, must not be approved without a human reviewer |
| `reviewed_by`, `reviewed_at` | staff id, timestamp | required to set `approved` |
| `medical_review_required` | boolean | true for clinical wording (services, articles, Q&A) |
| `medical_reviewed_by`, `medical_reviewed_at` | staff id, timestamp | required when the flag is set |

The public site **never falls back** to another language. A record without an approved translation in
the requested locale is hidden from listings and shows the explicit "not available in this
language" page if linked directly (current behaviour, see `TranslationUnavailable`).

### 1.2 Publishing states (base row)

`draft` → `in_review` → `scheduled` (optional `publish_at`) → `published` → `archived`.
Unpublishing returns to `draft`. Every transition writes an audit event.

### 1.3 Roles and permissions

| Capability | Admin | Content editor (staff, flag `can_edit_content`) | Medical reviewer (flag `can_review_medical`) | Inquiry staff | Patient |
|---|---|---|---|---|---|
| Create/edit drafts | ✓ | ✓ | – | – | – |
| Approve translation | ✓ | ✓ (non-medical) | ✓ (medical) | – | – |
| Medical approval | ✓ (if also a reviewer) | – | ✓ | – | – |
| Publish / unpublish | ✓ | ✓ only if all required approvals exist | – | – | – |
| Edit site settings (contact, social, integrations) | ✓ | – | – | – | – |
| Manage staff & roles | ✓ | – | – | – | – |
| View inquiries | ✓ | – | – | ✓ (assigned/permitted) | – |
| Any admin route | – | – | – | – | **never** |

### 1.4 Assets

- Uploads go to private storage first, then are approved for publication. Allowed: JPEG, PNG,
  WebP (images), SVG only for logos after sanitisation. Max 8 MB. Images are re-encoded for
  delivery; **originals are kept unchanged** with a SHA-256 hash (as `src/config/assets.ts` does now).
- Required metadata: alt text per locale, credit/owner, **publication consent** flag (people in
  photos), consent document reference, approved-by, approved-at.
- Never generate, retouch or regenerate people's faces. Background removal only with a
  non-generative method, and only after a person reviews and approves the output.
- The clinic logo is never recoloured; theme colours do not apply to it.

### 1.5 Validation & safety

- Server-side validation (Zod) for every write; length limits on all text; URLs must be `https:`.
- Rich text: a restricted Markdown subset rendered with sanitisation (no raw HTML, no scripts,
  no iframes except allow-listed video embeds generated by the system).
- Internal links chosen from existing routes (picker), so buttons can't point at dead pages.
- Optimistic concurrency (`updated_at` check) to avoid overwriting another editor's changes.
- Audit log for create/update/publish/unpublish/delete, recording actor, time and changed fields
  (no patient data in content tables).

## 2. Section requirements

### 2.1 Hero (homepage section 1)

| Field | Localized | Validation |
|---|---|---|
| `vision_words` (ordered list, default HOPE / TRUST / MIRACLE) | no (brand words) | 1–3 items, ≤ 12 chars, A–Z |
| `vision_meanings` (one per word) | yes | ≤ 40 chars |
| `intro` | yes | ≤ 160 chars, no medical claims (medical review if clinical wording) |
| `primary_cta` / `secondary_cta`: label + internal route | label yes | route from picker |
| `hero_image` | alt text yes | approved asset with consent; current: `/images/doctors/hero-doctors.jpg` |
| `doctor_lines` (names + licence numbers) | yes (Thai exact; others need approval) | from Doctor records, not free text |
| `specialty_lines` | yes | ≤ 80 chars each, medical review |

CRUD: single record (update only), versioned.

### 2.2 Service cards (section 2) and service pages

Base: `slug` (immutable after publish), `icon` (enum `serviceIcons`) **or** approved image,
`sort_order`, `visible_on_home` (bool), `published`.
Translation: `title`, `summary`, `introduction`, `suitability`, `process_steps[]`, `preparation`,
`faqs[]` ({question, answer}), `seo_title`, `seo_description`. All clinical fields require medical
review.
CRUD: create, update, reorder (drag & drop writes `sort_order`), hide/show, publish/unpublish,
archive (no hard delete while linked from packages/inquiries).
Homepage rule: show published + `visible_on_home` items in `sort_order` (currently exactly six).

### 2.3 Packages & promotions (section 3 and `/packages`)

Base: `slug`, `image` (approved asset), `price_amount` (optional, decimal), `currency` (THB),
`price_visible` (bool), `valid_from`, `valid_until` (dates, Asia/Bangkok), `cta_route` or
`cta_label`, `sort_order`, `show_in_home_carousel`, `published`.
Translation: `title`, `description`, `inclusions[]`, `exclusions[]`, `terms` (required before publish).
Rules: `valid_until ≥ valid_from`; expired items are hidden automatically (current behaviour,
re-evaluated at least hourly); price shown only if entered **and** `price_visible`; no discount
percentage field unless the clinic approves one with its own terms.
CRUD: create, update, duplicate, reorder, publish/unpublish, archive.

### 2.4 Success-story videos (section 4)

Base: `video_url` (input), parsed `provider` + `video_id` (via `parseVideoUrl`, allow-list
**YouTube, Vimeo**; TikTok/Facebook only after their embed terms are reviewed), `thumbnail_asset`
(fetched server-side for preview and stored after approval), `duration`, `sort_order`, `published`.
Translation: `title`, `summary` (no outcome claims unless medically reviewed), `captions_available` (bool).
Consent & authorization (required before publish): `consent_obtained` (bool), `consent_document_ref`,
`consent_scope` (website/social), `consent_expires_at`, `identifiable_persons` (bool),
`approved_by`, `approved_at`.
Metadata flow: the admin pastes a link → server validates against the allow-list → server fetches
oEmbed metadata/thumbnail from the provider's official endpoint only (no arbitrary URL fetching,
SSRF-safe allow-list, timeout, size limit) → editor reviews the preview → approver publishes.
Invalid or non-allow-listed URLs are rejected with a clear message.
Public rendering: click-to-load player (`VideoFacade`, `youtube-nocookie.com` / Vimeo `dnt=1`).

### 2.5 Why choose (section 5)

Fields: `image` (approved asset; current `/images/clinic/why-choose-doctors.jpg`), `show_vision_words`
(bool), translation `heading`, `description` (rich text, ≤ 1,200 chars, required before publish),
buttons ×2: translation `label` + internal `route` from picker (current: `/success-rates`,
`/facilities`).
Constraint: the success-rates page may only publish figures with source, period, methodology,
denominator and medical review fields completed.

### 2.6 Q&A / articles (section 6 and `/articles`)

Base: `slug`, `category` (enum, editable list), `published_at`, `cover_image` (optional),
`featured_on_home` (bool; homepage shows 2), `medical_review_required`.
Translation: `title`, `excerpt`, `body` (rich text), `seo_*`, plus the medical-review fields.
CRUD: full, with preview, schedule and archive.

### 2.7 Header / footer clinic information (site settings)

Single `site_settings` record (admin only): clinic names per locale (+ status provisional/verified),
`phones[]` (display format, validated), `email`, `line_id`, `address` (per locale; Thai required),
`opening_hours` (structured per weekday + localized notes), `map_url` (https, google.com /
maps.app.goo.gl only), `social` {instagram, tiktok, facebook}: https URLs on the official domains only.
Every field keeps a verification status (`pending` / `provided` / `verified`) exactly like
`src/config/site.ts`; unverified values render as placeholders.
Open item: the supplied footer text "คลินิกหมอหมอชัยณรงค์" contains a duplicated "หมอ"; the site
currently uses "คลินิกหมอชัยณรงค์" (from the approved branding decision) pending confirmation.

### 2.8 Contact form & Apps Script integration

Settings (admin only, stored server-side, never sent to the browser): `delivery_enabled` (bool),
`apps_script_url` (https `script.google.com` only), shared secret for request signing, notification
recipients, retention period, form field toggles (only optional fields can be hidden).
Requirements before enabling: anti-spam (honeypot exists; add rate limiting and optional Turnstile),
privacy notice approved, retention/deletion policy, test submission verified end to end. The UI
must only report success when the endpoint confirms (`{ "ok": true }`); otherwise it shows the
not-connected/failed message (current behaviour in `src/lib/inquiry/*`).
Inquiries themselves are **not** CMS content: they live in the protected inquiry module (Phase 6)
with staff-only access.

### 2.9 Translations dashboard

Matrix view: record × locale with status (missing/draft/in review/approved), medical review state,
last editor, last updated. Filters by section and status. Bulk "request review". Publishing a record
is blocked while a required locale is unapproved (configurable: publish per locale vs all locales).

## 3. Proposed data model (Phase 3/4)

```
site_settings(id, names jsonb, phones text[], email, line_id, address jsonb, opening_hours jsonb,
              map_url, social jsonb, field_status jsonb, updated_at, updated_by)
assets(id, storage_path, sha256, mime, width, height, alt jsonb, credit, consent_ref,
       publication_approved, approved_by, approved_at, created_at)
home_hero(id, vision_words text[], hero_asset_id, cta jsonb, status, updated_at)
home_hero_translations(hero_id, locale, intro, vision_meanings jsonb, specialty_lines text[], status, review fields)
services(id, slug, icon, image_asset_id, sort_order, visible_on_home, status, publish_at)
service_translations(service_id, locale, title, summary, introduction, suitability, process_steps jsonb,
                     preparation, faqs jsonb, seo_title, seo_description, status, review fields)
packages(id, slug, image_asset_id, price_amount numeric, currency, price_visible, valid_from, valid_until,
         cta_route, sort_order, show_in_home_carousel, status, publish_at)
package_translations(package_id, locale, title, description, inclusions jsonb, exclusions jsonb, terms, status, review fields)
success_stories(id, provider, video_id, thumbnail_asset_id, consent fields, sort_order, status)
success_story_translations(story_id, locale, title, summary, status, review fields)
why_choose(id, asset_id, buttons jsonb, show_vision_words, status)
why_choose_translations(why_choose_id, locale, heading, description, button_labels jsonb, status, review fields)
articles(id, slug, category, cover_asset_id, featured_on_home, published_at, medical_review_required, status)
article_translations(article_id, locale, title, excerpt, body, seo_*, status, review fields)
integration_settings(id, inquiry_delivery_enabled, apps_script_url, secret_ref, recipients, retention_days)
audit_events(id, actor_id, action, entity, entity_id, changed_fields text[], created_at)
```

All tables: RLS enabled; public `anon` role can `select` only published rows with approved
translations (via views); writes only through server actions checking role flags. pgTAP tests cover
allowed and denied cases for each role.
